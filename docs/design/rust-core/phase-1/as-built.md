## The bridge freeze

Built at T1.10e (E50), with three fail-open fixes at T1.12; moved from design.md's "Host-held semantics" at T1.12b, where the freeze's rules stay.

The bridge freeze (E50, as built at T1.10e; its method changed at fix round 2, its module fingerprint made structural at round 3, its reading made the interpreter's at round 4): a tripwire for undeclared changes to the core route's Python bridge, so a new product rule lands in Rust; its threat model is honest drift, not deliberate obfuscation (E56(b), "Harness scope").

`scripts/rust_core/bridge_freeze.py`, run by `l0_deps.py` and so in `prepush.sh`'s cheap tier and CI's `rust-lint`, freezes every function of `_rust/schema.py`, `_rust/materialize.py` and `_rust/predict.py`, and in the files shared with the old route the functions the script's `COVERED` names: in `client.py`, `query.py` and `materializers/relational.py` the ledgered functions and those the core route reaches through them; in `schema.py`, `adapters/relational.py`, `base.py`, `result.py` and `decompose.py` the bodies of the ledgered rules (the five T1.21d rows, `_preflight`, `check_request_against_model`, `PredictionResult.merge`, `parts_of`); and the entry points `SDMClient.predict`, `PredictiveQuery.materialize`, `RelationalMaterializer.materialize` and `Schema.from_source`, with `RelationalMaterializer.__init__`, which holds the index once-flag. It also freezes each such file's skeleton, and `_rust/__init__.py`'s: the whole module in order and in scope, every function's body (covered or not) replaced by `pass`, so a module statement, an import, a class attribute moved in or out of a class, and a method, dunder or property added to, removed from or renamed on any class change it.

`COVERED` is reviewed code; the five files of rule bodies carry no F7 header, since they are not deleted, and the self-test holds every frozen file to being a bridge file of `l0_deps.py`, part of the `_rust/` package, or the home of a rule this table names.

The tripwire is the gate. The committed baseline, `scripts/rust_core/bridge_freeze.json`, holds a fingerprint of each frozen function and skeleton: the SHA-256 of its syntax tree without positions or docstrings, serialized alike on every Python version. Against the merge base with the base branch (`--base`, else the environment's `SDM_FREEZE_BASE`, else `origin/rust-core-phase-1`, a blank one refused; E56(c)), every entry whose fingerprint differs, and every one that is new or gone (a function added, removed or renamed, a function newly covered or let out, a file leaving the freeze), must be declared in `scripts/rust_core/bridge_changes.json` with one reason: `moved` (a rule moved into Rust, naming its task), `allowance` (growth under an `ALLOWANCES` entry, below), `refactor` (an edit that keeps behaviour; a rename is a change, its new name and the skeleton declared a refactor and its old name gone) or `gone` (an entry that left the freeze; a gone entry is declared gone, or moved when its rule moved into Rust).

It fails on an undeclared change; on a stale declaration (its entry unchanged); on a change declared only by an entry the merge base's declarations already hold (spent: each change states its own reason; spent entries of unchanged code are inert and may be pruned); on `gone` for an entry that is not gone, or a gone entry declared anything else; and on a `moved` that names no task. It reads each frozen file's bytes as the interpreter does and refuses a source-encoding cookie other than UTF-8 (a `raw_unicode_escape` or `utf-7` cookie runs what a UTF-8 reader takes for a comment), and, whatever spells a cookie (one behind a lone CR, which `tokenize.detect_encoding` misses, included), a file whose syntax tree parsed from its bytes differs from the one parsed from its UTF-8 text, where any cookie is ignored (T1.12, seeded in `selftest.py`), and it refuses a directory beside a frozen module with the module's name, whose package would be imported in its place. So the dispatch forms the counts could not see, a zero-count helper, and a structural edit (a class attribute moved to module scope, a new `__getattribute__`) fail as changes no one declared, and review judges every declared reason's direction.

The counts are the secondary check: per entry the baseline also records `raise` and `assert`, `warnings.warn`, branches (`if`, conditional expressions, `while`, `for`, `match` cases, comprehension conditions, `except` handlers, `contextlib.suppress`, each `and` and `or` operand after the first) and calls (first-party functions and classes by name, which gate, and methods of unresolved objects, listed for review). Per entry, against the same entry at the merge base (its baseline entry; for one newly covered, its body in the base's own source; for a rename, the gone entry of the same shape), a count may rise, and a named first-party call appear, only under that entry's own `ALLOWANCES` entry, declared `allowance`: one the base's copy of the script does not already hold, under a row of the base's decisions.md whose status reads "approved by owner" and which names `<file>::<qualified name>`; so a row added in the same change grants nothing. The one exception: entries declared `moved` in one change net their counts and dropped calls against each other across the frozen files, so a rule moved from `schema.py` into `_rust/` glue needs no allowance while the moved entries together add no rule; a `refactor` or `gone` entry is never paid for by another's drop, and an entry let out of the freeze whose body the file still defines moved nothing, so adds nothing: neither its counts nor its calls fund another entry, and a let-out file that cannot be read or parsed counts as still defining every entry (T1.12, seeded in `selftest.py`).

The round-1 heuristics that tried to see dispatch (references to first-party names, with exemptions for upper-case names and method references) are gone: the tripwire makes them redundant, and they gave false positives (`typing.cast` to a first-party class, a local shadowing an import, `.copy` on a value), which are now declared refactors.

`selftest.py` seeds every evasion of the three review rounds as an undeclared change, each declaration rule, the netting of moved entries and its refusal for a refactor, a file leaving and joining the freeze, the allowances' rules, and missing, empty, retyped, deep and wide evidence, with controls that pass.

What it does not see, plainly, and review holds as it holds the owners in this table and each declared reason: a rule added inside the body of an existing function `COVERED` does not name (a first-party helper covered code already called); and any code outside the frozen files: data covered code reads (for example `models.py`'s `RELATIONAL_LIMITS`), module code rebinding a covered name, a dunder set on a frozen class from elsewhere, a method on a superclass that is not frozen.
