# Phase 1 decisions

Decisions made for Phase 1, newest last.
Rows marked "orchestrator, owner to confirm" were made by the orchestrator while the owner was away, so the design could be written; each stands until the owner confirms or changes it, and T1a.1 closes only when every one is settled.
Standing decisions are in [migration-plan.md](../migration-plan.md) section 2 and [phase-0/decisions.md](../phase-0/decisions.md).

| # | Decision | Reason | Status |
|---|---|---|---|
| A1 | Phase 1a creates `sdm-contract`, `sdm-core` (a skeleton with the single Run state machine), `sdm-host`, `sdm-py`, `sdm-testkit` and the interim parser crate; the pure-Rust test host is a 1a deliverable | S0 green and a real wheel need the parser, the adapter, the host layer and a binding, which the plan's 1a row does not list; L0 and the per-change gate already require a pure-Rust host passing the contract subset | orchestrator, owner to confirm |
| A2 | "S0 green in Python" means: the public Python call that validates PQL (`materialize()`, which validates before reading data), forced onto the core route through the private routing seam, gives the same outcome as the reference, compared on validity, error code and span, not message text | S0 has no public validate method and no path switches before Phase 3; codes and classes are promised, message text is not | orchestrator, owner to confirm |
| A3 | The interim parser crate is `sdm-pql-interim`; the native module is `sdm_client._native`; the reference guard's name list includes it, updated on `rust-core-reference` if needed | The name `pql` is reserved for the PQL team's crate; one crate makes the Phase 5 deletion one directory and one edge; the guard must know the real module name | orchestrator, owner to confirm |
| A4 | L0: Python-emulation modules are allowed only in `sdm-pql-interim`, on an allowlist that expires when the PQL team's crate replaces it, and are banned everywhere else | The interim parser emulates defined PQL behavior (PK-4, PK-5); a blanket ban would block it, and a lax guard would let pandas emulation back into other crates | orchestrator, owner to confirm |
| A5 | Phase 1 gates are L0, L1, the L2 subset and the ratchet; L4 SQL goldens and L5 conversion tables apply only to what the 1b inventory needs (DuckDB; pandas 2 and 3); the rest of L4 and L5 starts in Phase 2 | The provider kit and the full L5 matrix are Phase 2 deliverables; stating the subset avoids a gate that is silently unmet | orchestrator, owner to confirm |
| A6 | The register moves to format `sdm-register/2`, with per-case old and new outcomes and decision references that can point to any phase's decisions file | The ratchet accepts a changed outcome only when an entry states that case's exact old and new outcome, and `decision_ref` today can only name a Phase 0 row | orchestrator, owner to confirm |
| A7 | The zone check is done: `jiff` meets DT-1 and DT-2 on the T0.6 corpus, and `chrono-tz` and `tzfile` do not; `jiff` becomes the one calendar and zone library, with the host passing its zone directory explicitly and a bundled fallback; `chrono-tz` is banned | The probe matched all 2,808 zone answers and all 208 offset answers with `jiff`, using both the host directory and the bundled database; `chrono-tz` stops rules at 2099 and embeds its database, `tzfile` ignores rules after 2037; the core must not read the environment to find the database | orchestrator, owner to confirm |
| A8 | One CI job tests the `pyarrow` 10.0.1 floor in Phase 1 (`wheel-smoke` on Python 3.10 with pandas 1.5.3) | The binding needs `_export_to_c` below pyarrow 14, and the floor is a support decision (decision 23); leaving it untested until Phase 2 would hide a binding defect | orchestrator, owner to confirm |
| A9 | A minimal status page generator (git and CI status into one markdown page) is built in Phase 1a | The plan requires a generated status page and Phase 0 built none; kept small so it is not new harness growth | orchestrator, owner to confirm |
| B-D2 | Arrow is pinned to the major that the Rust DuckDB crate uses at the reference's DuckDB version; `arrow`, `duckdb` and `pyo3` are bumped together | One Arrow major keeps the pure-Rust host free of FFI glue between two Arrow versions; the archive's newer major would force one | orchestrator, owner to confirm |
| B-D3 | maturin becomes the client's build backend on the epic branch; CI's `build` job, which asserts five pure wheels today, takes the client wheel from the new native wheel job | Decision 20 puts the core in the client wheel with no pure-Python fallback; `main` is untouched | orchestrator, owner to confirm |
| B-D6 | One shared Arrow normalization table, in `sdm-host`, turns `large_*`, `timestamp[s]` and `[ms]`, `large_list` and `fixed_size_list` into the closed set without loss, or refuses by name | Written once, Python and Java cannot drift on it; native-to-Arrow tables stay in each host | orchestrator, owner to confirm |
| B-D7 | The routing seam is private and read per call, with an environment variable (`SDM_CORE_ROUTES`) for tests; it is not public API and is deleted in Phase 5 | The first attempt's import-time flag made in-process switching unreliable | orchestrator, owner to confirm |
| B-D8 | Reference results are committed as expected observations, regenerated locally at each gate with the reference commit recorded, so CI compares without running the reference | Decision 5 keeps reference runs local, yet the per-change gate needs a comparison in CI | orchestrator, owner to confirm |
| Q1 | Default: in Phase 1b, key sets travel as one JSON text parameter built from the Arrow key column; Phase 2's provider kit measures passing them as Arrow | DuckDB's Python driver cannot bind an Arrow array as a parameter; the JSON is exact for every integer width, text and decimals as text | orchestrator, owner to confirm |
| Q2 | Default: DuckDB's `QueryLog` (statement text without parameters) is the SQL trace for `python-old` and `python-ref`, and their parameters are compared through the rows returned; core runners record parameters from the step trace | It needs no patching of the reference and sees every cursor | orchestrator, owner to confirm |
| Q3 | Default: whether ORD-1's tie order reaches a payload is measured in T1b.11; until then the comparator does not normalize tie order, and a stable order is proposed as a register change if ties reach a payload | numpy's default sort can dispatch to platform-specific code, so copying it is fragile | orchestrator, owner to confirm |
| Q4 | Default: the PQL asks stay unsent and nothing in Phase 1 waits on them; the adapter's validated-query format is offered to the PQL team as a starting point when they are sent | Decision 31 | orchestrator, owner to confirm |
